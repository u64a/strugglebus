## Measurement contract

**Scope:** all Python under `src\strugglebus`, `scripts`, `deploy\files`,
`deploy\roles\guest_base\files`, `deploy\filter_plugins` and
`deploy\callback_plugins`: 29 application files and 31 operational/release
helper files. An independent source inventory includes never-imported files;
all 60 are present in coverage output.

Exclude tests and test harnesses (`tests`, `deploy\tests`, `deploy\validate.py`),
the new reporting glue (`scripts\quality_baseline.py`), dependencies, generated
files, SQL, shell/PowerShell, Ansible YAML/Jinja and embedded browser
JavaScript/HTML/CSS. These exclusions do not grant a later quality exception
to changed production logic in those languages. This is a Python baseline,
not whole-system behavioral or UI coverage.

**Complexity C:** Radon's pinned default cyclomatic complexity of each AST
`FunctionDef`/`AsyncFunctionDef`, including methods and nested functions, with
assertions counted. Class aggregate scores are not function scores.

**Function mapping:** identity is repository-relative file, lexical qualified
name and definition line. Each function owns its body range; nested function
bodies and nested class bodies are subtracted. Nested declarations/decorators
remain with the enclosing caller where applicable. Methods and closures get
their own rows. Repeated names such as property getter/setter remain distinct
by line. Traversal includes conditional/else definitions. Module/class-level
statements remain in file totals but have no invented function CRAP.
Anonymous lambdas/comprehensions have no separate function row; the enclosing
Radon score and coverage.py's physical-line model apply. Same-line constructs,
boolean conditions and conditional expressions are not separately proven paths.

**Coverage T and adapted CRAP:**

```text
If a function has measured branch exits:
    T = covered branch exits / (covered + missing branch exits)
Otherwise, if it has executable statements:
    T = covered statements / (covered + missing statements)
CRAP = C^2 * (1 - T)^3 + C
```

Coverage.py reports executable statements and branch arcs. Arc ownership follows
the **source** line, including exits outside the function. This is a
**branch-exit CRAP adaptation with a branchless statement fallback**, not the
original basis-path metric, MC/DC, assertion quality or path-combination
coverage. No repository-wide percentage is substituted for a function's T.
Expressions can raise Radon complexity without creating coverage.py branch
exits; a fully executed line does not prove both expression outcomes.

The run traces the pytest process and its Python threads. **Child Python
processes and clean-installed wheels are not instrumented**; subprocess-only
execution therefore remains uncovered in this baseline even when its test
passes. Skipped Linux paths also remain uncovered, not omitted. Coverage
exclusion and partial-branch regex lists are empty; coverage.py/Python's
intrinsic treatment of non-executable and constant-folded code still applies.

Missing file data or no executable body produces `coverage: null`, `crap: null`
and an explicit status. Reporting exits 2 for incomplete measurement while
retaining available scores. Source/test/config/environment drift and stale or
non-branch coverage are rejected. A score report, even with exit 0, is not
evidence that pytest passed and is not a merge gate.

The 22 reporting tests exercise C=10/T=0 -> 110, C=10/T=1 -> 10, fractional
coverage, invalid inputs, real branch arcs, branchless and async code, closures,
nested classes/decorators, conditional definitions, repeated method names,
missing/bodyless data, threshold boundaries, inventory, report output and
source/freshness checks.

## Changed-code denominator and later policy

M0 changes **zero production functions**: its changed-production denominator is
empty / not applicable, never "100% covered." No baseline delta is claimed
against an earlier unmeasured revision.

For a later slice, explicitly list new/materially changed functions by
file/name/definition line, including affected closures and methods. Use the
**whole current owned function body**, not just added lines: all its branch
exits are the denominator, or all its executable statements when branchless.
Report each function plus weighted covered/total exits for the changed set;
do not let a pooled percentage hide a below-target function. Renames/moves
require lineage review, deletions contribute no executable denominator, and
module-level or otherwise unmeasured changed logic requires separate evidence,
not a silent exclusion. This report does not implement a diff selector or gate.

Keep the approved policy: C <= 10; adapted CRAP <= 15, review above 15 and below
30, and an approved justified exception at >= 30; branch coverage >= 90%.
Branchless functions report statement coverage instead of a fictional branch
pass, with a documented exception below 90%. Exceptions identify the exact
scope, reason, risk, evidence, approving reviewer and re-review condition in
the slice's report/PR. Missing evidence cannot pass. API/caller simplicity,
atomicity and relevant authorization/freeze/recovery failure-path assertions
remain separate mandatory review evidence. This baseline grants no exceptions.
